## 0. Top operator ask: git/production divergence on the signup form

Before anything else: **git `main` and the live site currently disagree on the
Buttondown signup URL, and this needs an operator decision, not another
automated edit.**

- `main` (this checkout) has, on every page with a signup form:
  `https://buttondown.com/api/emails/embed-subscribe/morguelabs`
- The live site (fetched fresh with cache-busting query strings against
  `/`, `/autopsies/nba-fatigue`, `/autopsies/congress-etf`, this run) serves:
  `https://buttondown.com/api/emails/embed-subscribe/morty-morguelabs`
- `git log --all` on every HTML file in this repo shows `morty-morguelabs`
  has **never** existed in git history. There is no merged commit that could
  have produced what's live.
- PR #15 ("Fix Buttondown signup endpoint," opened 2026-08-13, still open
  and in draft) proposes exactly this change, with verification evidence in
  its description: `embed-subscribe/morty-morguelabs` 302-redirects (real
  slug), `embed-subscribe/morguelabs` 404s (dead slug), and the public
  archive at `buttondown.com/morty-morguelabs` is live. PR #15 is **not
  merged.**
- Yet the live site already serves the PR #15 content. Something applied
  that fix directly to production outside of git, the one deploy path this
  publication is supposed to have (push to `main` -> Cloudflare Pages).
- Corroborating evidence the fix is real and working: Buttondown now shows
  **1** active subscriber, added 2026-08-14, `source: embedded_form`,
  `referrer_url: https://morguelabs.com/` — i.e., a real visitor used the
  live (`morty-morguelabs`) form successfully, after PR #15's investigation
  and after production apparently already had the fix.

Net effect: production is not a strict function of `main` right now for at
least this one string. Everything else checked this run (Quantocracy badge,
Autopsy №005 card, RSS order) matches `main` exactly, so this looks like a
one-off manual patch to stop the subscriber bleed, not a broader drift.
**Recommend:** merge PR #15 so `main` matches what's actually live, and
separately confirm how that content reached production ahead of the merge —
if that path is a Cloudflare dashboard quick-edit, fine and worth knowing
about for next time; if it's something else, worth knowing that more
urgently. I did not touch PR #15, per the rule against editing other
in-flight PRs.

One consequence: my own health check in §1 below is checking for the OLD
(dead) slug string, because that's the literal string specified in my
standing instructions. It fails, correctly, since the site no longer serves
that string, it serves the fixed one. That check's expected string should
be updated to `embed-subscribe/morty-morguelabs` once PR #15 is merged and
the slug change is confirmed as the operator's intent.
